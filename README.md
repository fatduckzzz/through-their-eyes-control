# 对照组材料：科普文字版

### ▶ [**打开网站 · fatduckzzz.github.io/through-their-eyes-control**](https://fatduckzzz.github.io/through-their-eyes-control/)

RCT 的**对照组**材料。实验组是沉浸式交互网站，本站是信息内容与之匹配的科普文字版。
两组**信息内容相同**，只有**呈现形式**不同——这是本实验的自变量。

- 实验组网站 → [fatduckzzz.github.io/through-their-eyes](https://fatduckzzz.github.io/through-their-eyes/)
- 投放时带上答卷编号：`?pid=答卷编号`

```
index.html    全部内容，分 16 屏阅读
style.css     朴素排版：无动画、无色彩编码、无模拟
pager.js      分页推进与进度条
tracker.js    曝光计时 / 分节覆盖 / 完成码（与实验站逐字节相同）
tools/        完成码解码脚本
```

本地预览：`python -m http.server 8000`。无构建步骤、无依赖。

## 一、操纵了什么，控制了什么

| | 实验组 through-their-eyes | 对照组（本仓库） |
|---|---|---|
| **信息内容** | 相同 | 相同 |
| 人称 | 第二人称（"你叫亚历克斯"） | 第三人称说明文 |
| 视角占据 | 有：选择色觉类型、代入一整天 | 无 |
| 色觉模拟 | 有：SVG 滤镜实时改变画面 | 无 |
| 交互 | 有：选择、反馈、开关 | 仅「继续」翻页 |
| 叙事张力 | 有：悬念、反转、日落揭示 | 无 |
| 情绪化视觉 | 有：暗色影院感、动效、氛围 | 无：白底、正文排版 |
| 当事人自述 | 第一人称引语 | 第三人称转述（内容相同） |

**因此可归因的自变量 = 叙事化 / 具身化 / 交互式呈现形式。**
如果实验组共情得分更高，不能被解释成"实验组看到的信息更多"。

**配图（新增）：** 第七节的五个改法各配一组静态「改前 / 改后」内联 SVG；第八节的 8.1–8.6、8.8 配上实验站**同一批**截图（伦敦地铁图、日本信号灯、Google 图标前后、Spotify、Trello、Cividis、WCAG 标识、EnChroma）。

在此之前，实验站用 13 张真实截图展示的东西，对照站只有文字——一张地铁图上的线路纹理，散文说不出来，这属于**信息不对称**而非形式差异。补图之后两组在"看到了什么"这一层才真正对齐。

三条约束：（1）只用实验站已有的素材，换成别的图等于给对照组引入实验组没见过的信息；（2）Trello 那张动图取静帧，对照站保持无动画；（3）实验站第七节是**可点击切换**的前后对比，交互属于操纵变量，所以对照站把两个状态并排静态呈现。

**篇幅核对（实测）：** 对照组 7,482 个汉字；实验组文案总量 8,114 字，但其中约 1,597 字是按色觉类型与选项分支的备选反馈，**单个被试实际只会读到约 6,759 字**。
即对照组的文字量**不少于**实验组——排除了"对照组内容更少"这一替代解释。

逐节比对的结论是两组已经匹配：wins 相关材料 1,894 对 1,918 字（对照站第八、九、十节合起来看），第六节与实验站的 EnChroma 屏逐条对应。对照组的字数"超出"是散文相对交互演示的表达开销，删减反而会破坏内容匹配。

## 四、曝光测量（`tracker.js`）

**这份文件与实验站的那一份逐字节相同**，两组必须用同一套计时口径，否则曝光时长不可比。改一边就要同步改另一边。两站都已接好：

```html
<body data-arm="control">   <!-- 实验站写 data-arm="narrative" -->
<script src="tracker.js"></script>
```

记录内容：

- **有效阅读时长** —— 页面不可见时暂停，连续 60 秒无操作时暂停（防挂机）
- **滚动深度** —— 25/50/75/90/100% 里程碑
- **分节覆盖** —— 每个 `section[id]` 首次进入视口的时刻；分页后由 `pager.js` 每翻一页显式补记
- **完成码** —— 达到 `MIN_ACTIVE_SECONDS`（**480 秒 = 8 分钟**）后才可生成

闸门原本是 360 秒。对照组正文约 7,500 字，精读需 19–25 分钟，6 分钟就能拿码等于闸门形同虚设，故上调。

### 完成码携带数据

本站没有后端（`CONFIG.ENDPOINT` 为 `null`），`localStorage` 里的事件流回收不了。所以完成码不是单向哈希，而是**把关键指标编码进码里**——被试把码填回问卷，数据就随之回到你手上：

```
TTE-C-5ME80Q  →  { arm: 'control', minutes: 22, sectionsSeen: 17,
                    maxScrollPct: 100, valid: true }
```

`TTE-` 之后的 `C` = 对照组、`N` = 实验组，**可以直接从答卷核验被试实际进了哪个站**——分组失败、串组、跳过材料都查得出来。

解码整份答卷导出：

```bash
python tools/decode_codes.py 答卷.csv --column 完成码
```

完成码是纯前端生成的，**可以伪造**。它是依从性信号，不是防作弊机制，请与问卷里的注意力检查题合并判断。

参与者编号从链接参数读取：`index.html?pid=答卷编号`。

## 五、还需要注意的两个混淆

1. **时间不等长。** 实验组因为有交互、动画、场景切换，wall-clock 时间天然比读一篇文章长。如果实验组共情更高，可能只是因为"接触时间更久"而不是"形式更有效"。
   处理办法：`tracker.js` 已经在记录 `activeSeconds`，**把它作为协变量放进模型**（或做一次以时长匹配的子样本分析）。建议正式投放前先跑 5–10 人小规模预试，看两组实际时长差多少。

2. **新奇效应。** 交互网站本身比文章更"新鲜"，这份新鲜感可能贡献一部分效应。可以在问卷里加一两道题（如"这份材料的形式让我觉得新颖"、"我愿意把它分享给别人"）作为辅助测量，用来在讨论部分区分"共情"与"新奇/趣味"。
